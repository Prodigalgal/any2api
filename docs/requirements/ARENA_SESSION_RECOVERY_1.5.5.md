# Arena 已有会话恢复与请求准备阶段阻塞修复（1.5.5）

## 目标与授权

用户选择复用已有且验证过的 Arena 会话，随后要求继续推进。使用现有账号、浏览器状态和原关联出口复核，不新建管理台人工验证入口。历史成功只用于筛选候选，不能等同于当前验证码验证已通过。

## 范围与影响文件

1. 先以完整保存状态及原 Self Proxy 出口复核少量历史成功账号；明示原生流程、登录有效、生成有效的区别，不批量生成探测，不复用历史单次 Token。
2. `official_browser.py`：现有关闭流程的 context/browser/driver 等待必须受已有 `browser_cleanup_timeout_seconds` 约束；残留进程终止移至线程，最终释放浏览器预算和隧道引用，保留正常缓存复用与进程归属保护。
3. `provider_api.py`：统一 Action 流使用已有 `inference_first_frame_timeout_seconds` 限制首个内部帧的准备等待；返回明确超时错误并清理迭代器，不能把未进入生成的等待挂到客户端取消。持续产生帧的正常长流不增加总时长限制。
   `page_fetch_browser.py` 的非流式目录/保活请求也使用相同预算，包含等待账号槽、恢复浏览器、页面请求与保存状态，防止后台非流式操作永久占住推理所需槽位。
4. 只有在当前证据确认会话过滤破坏恢复时才调整 Arena 状态策略；不扩大通用 Cookie/域名权限，不保存 Google 账号登录态或客户端私密正文。
5. 补齐关闭卡住/失败/取消、预算与隧道释放、首帧超时/正常长流/客户端取消回归。源码修复占用新补丁 1.5.5，不能复用已部署 1.5.4。

## 验收与回滚

- 成功路径必须有真实有效回答或合法工具调用；若候选会话仍需图形验证，明确报告未恢复，不把 Cookie/目录 200 当作验收。
- 卡住的关闭动作有界完成，事件循环健康不被进程终止等待阻塞；请求准备超时返回 OpenAI 可解释的失败，取消后不永久占用池槽。
- 本地相关/全量回归、版本与 JAR 契约、CI 不可变镜像、GitOps、Pod/digest/API 和定向线上请求全部按发布链验证。
- 无数据库迁移，无 OpenAI 公共契约变化；DeepSeek/Qwen 停用与其他厂商代理绑定保持。回滚使用 1.5.4 的不可变镜像组合。
