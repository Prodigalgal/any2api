# 当前任务：MiniMax 每日签到生命周期

## 目标

为统一生命周期契约增加通用的 `daily_checkin` 语义，由 MiniMax 首先实现，复用现有 Camoufox Browser Runtime，完成“签到领取额度 -> 推理测活 -> 周期签到”的账号激活链路。

## 范围

- 自动化服务在通用 provider 操作契约中暴露 `daily_checkin`，由 `DailyCheckinStrategy` 定义共享语义，各厂商在独立策略模块中具体实现。
- 通过官方 Web 前端同源请求调用签到状态与领取接口。
- Java 生命周期调度支持签到操作、账号激活优先签到和每日重调度。
- MiniMax runtime rule 支持签到 endpoint path，保留旧规则缺字段时的安全 fallback。
- 补齐自动化、Java、Web 文案和架构契约测试/说明。

## 非目标

- 不新增厂商官方渠道 API。
- 不绕过验证码、风控或额度限制。
- 不改变其他厂商现有生命周期操作和推理传输。
- 不在本轮批量注册新账号。

## 验收标准

- `daily_checkin` 仅由声明该能力的厂商暴露，其他厂商行为不变。
- MiniMax PENDING 账号激活时先执行签到；签到成功或已签到后再执行推理测活。
- 当前日已签到时不重复领取；未签到时领取成功后记录安全的签到元数据。
- 认证失效进入既有重新认证链路；签到失败可重试且不误标 ACTIVE。
- 自动化与 Java 相关测试通过，并在 K8S 使用真实 MiniMax 账号完成签到状态、领取/已领取、额度后推理验证。
