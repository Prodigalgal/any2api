# 1.5.11 Automation 容量与积压恢复

## 目标

修复持续运行后浏览器名额等待、同步线程和清理互相阻塞的问题；按用户授权提高内存预算，恢复普通推理和后台维护，并收尾没有有效执行租约的历史操作。

## 范围与影响文件

- `automation/`：后台同步工作与清理使用独立有界执行资源；取消传播至浏览器名额等待，名额等待具备总时限；前台保留浏览器容量，内部健康检查观测任务进度。
- `deploy/gitops/automation-runtime-resources.yaml`：共享 Automation/Arena 内存上限均为 6Gi、request 均为 2Gi；共享浏览器预算为 4，保持 CPU、代理及厂商限流。
- `backend/observability/`：周期对账过期 RUNNING，仅关闭没有匹配有效执行租约的生命周期/注册操作，保留仍有所有权的操作。
- 同步版本、针对性并发/取消/真实 PostgreSQL 回归、发布验收记录。

## 非目标与兼容

不改 OpenAI 客户端契约、账号权限、代理绑定、注册计划或保活周期；不恢复生成探活和模型可用性判定；DeepSeek/Qwen 保持停用。不以删除历史数据掩盖积压，不新增数据库结构或外部服务。

## 验收与测试

1. 默认工作线程被同步名额等待占用时，清理和 reaper 仍能完成；取消后等待工作退出，不再取得或泄漏名额。
2. 后台排队与实际执行均有界，取消不提前释放仍在运行的同步工作名额；保留 ContextVar 中的关联信息。
3. 浏览器总量不超过预算，后台留出前台容量；健康检查不访问厂商、不生成文本。
4. 对账关闭孤立旧操作，保留近期操作及匹配当前有效租约的操作；重复执行幂等、并发节点由事务 advisory lock 协调。
5. 全量 Automation、Backend、Ruff、Web 构建与版本契约通过；CI/GitOps、运行版本/资源/健康、少量真实输出和维护推进分别验收。

## 发布与回滚

占用新补丁版本 1.5.11，所有组件版本一致，使用新的不可变镜像。沿既有部署授权提交、CI 和 Argo 发布。回滚使用 1.5.10 不可变镜像及对应资源补丁；不回退已完成的历史终态修正，无数据库迁移。连续运行稳定性需要后续真实流量观察，短窗口不扩大为全部账号和客户端验收。
