# Arena v3 验证回归定位与恢复

## 目标与现状

用户在 1.5.2 发布与 IPv6 接入后要求继续打通 Arena，指出过去不频繁弹出 v2。目标是定位正常 v3 流程失效的原因，恢复真实 OpenAI 下游调用，不能以匿名页面、账号 keepalive 或目录 200 替代推理验收。

- 当前生产 1.5.2，源码 `48718c9`，新代理固定 IPv6 且浏览器可加载官方页面；两条新 Max 自然请求仍 v2/超时。
- 历史最后成功普通推理开始于 2026-10-16 18:12:12（UTC+8）；17、18 日 Max 暂无成功。不能将用户描述直接归因于代理或平台变更。
- 最近 24 小时 346 条 anti_bot_rejected 的快照均为 recaptcha_escalation，而非代码对 prompt_rate_limit 的 v2 降级。

## 范围与方法

1. 对齐成功时间、账号、模型、协议与源码变化，核验旧成功记录是否有有效输出。
2. 读取当前官方页面与公开脚本，核对 v3 site key/action、token 获取与消耗、请求字段/端点和响应语义；仅保存公开资产或脱敏元数据，不记录账号 cookie/token/提示正文。
3. 用独立诊断浏览器复现官方流程，先拦截提交核对真实请求结构；确有必要时仅做少量定向普通请求验证，不恢复定时生成探活或模型可用性判定。
4. 比较同账号、同固定出口、同浏览器会话中的官方交互与桥接调用；保留进程保护、隧道复用、三作用域绑定和其他厂家行为。
5. 如需源码修复，使用新的补丁候选版本，运行回归、不可变镜像、GitOps 与真实链路验收；不覆盖已发布 1.5.2 制品。

## 影响与验收

- 可能涉及 `arena_browser.py`、`arena_settings.py`、局部 Runtime 事件/超时边界及相应用例；以证据决定最小修改。
- OpenAI Chat/Responses 契约保持，错误不能伪装成成功，不新增付费验证码 SaaS，不触碰 RCM、DeepSeek/Qwen 和其他厂家绑定。
- 验收需存在真实有效正文或合法工具调用，记录 request_id、事件类型与长度；同时验证错误、取消、超时、凭据/出口切换和资源回收。若官方要求人工验证码或账号操作，则明确具体阻断与证据，不盲目重试消耗额度。

## 1.5.3 / 1.5.4 修复规格

- 已确认：同一历史成功账号在新固定 IPv6 的官方原生页面也返回 403 `recaptcha validation failed`；`cx` 缺失不能解释全部故障。官方 v3 site key/action 未变，同源绝对 URL 也会补齐部署请求头。
- 请求兼容：复用页面自身导出的 `buildProgrammaticClientInteraction` / `packClientInteraction`，记录真实 programmatic 上下文，不复制盐值、伪造可信事件或硬编码压缩格式；保留官方上传能力。
- 资源边界：移除无人读取且会保存正文/Token 的 fetch 调试拦截；v2 等待必须遵守本次请求截止时间并清理定时器/widget，辅助任务随流结束或取消回收；v3 Token 不可用时明确失败，不能继续发送缺 Token 的请求。
- 回归：执行 JS 行为测试，覆盖正常流、v2 超时/截止/已解决重试、Token 缺失、上传与交互导出共存；执行异步辅助任务结束/取消测试及 Automation 全量检查。
- 发布：兼容补丁占用新版本 1.5.3；保持 OpenAI 契约和数据库不变，回滚点为 1.5.2 镜像组合；生产恢复判定仍需真实有效输出，不能用兼容修复通过替代。
- 发布门禁复查发现 v2 iframe 选择错误：页面含隐藏 v3 anchor 和可见 v2 anchor，旧选择器在现场得到 checkbox 数量 0，新 `:visible` + `first` 选择器得到 1 且可见。1.5.3 CI 在 GitOps 发布前取消，版本和已生成制品不复用；新增修复候选占用 1.5.4，补齐选择器回归后重新执行完整发布链。
