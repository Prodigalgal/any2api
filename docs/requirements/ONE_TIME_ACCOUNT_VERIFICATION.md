# 账号入库一次验证与移除模型可用性判定（1.0.0）

## 目标与范围

按用户最新要求，每个账号入库后最多执行一次轻量文本生成，验证账号能调用；停止定时模型探活和生命周期重复生成。移除模型健康/可用性预测及其调用拦截，模型目录只表达发现、启用、能力和参数。同步完成已验证的 DeepSeek HTTP 200 JSON 业务拒绝修复。

## 行为与契约

- 首次验证使用当前厂商配置的基础模型，一条短消息，无工具/技能，不执行高级模型探活、模型遍历、传输回退或生成重试。
- 每个 account_id 的一次预算由 PostgreSQL 唯一约束永久记录；先提交领取，再调用外部 WEB。并发、重启、重新导入相同账号、保活/刷新和重复管理请求不能再次消费预算。失败或运行中断也不自动重新生成，不把未确认结果伪装为可用。
- 当前七家 526 个账号全部具有历史验证记录，迁入首次验证记录时不扫描普通推理账本，旧账号不重新批量生成；HISTORICAL 的新表时间表示导入时间，原验证时间仍保留在账号 metadata。定期保活、凭据刷新、签到保留各厂商已有非生成动作；重复管理验证返回已记录结果，不改变当前账号状态。
- 删除定时 ModelProbeScheduler、ModelAvailabilityGuard、模型健康 SQL 聚合和公开 available/健康扩展字段、控制台模型可用性展示及模型健康指标；移除基于模型失败率的熔断拦截。保留账号权限/租约/实际资格、并发队列、参数校验、普通推理账本和故障观测。
- OpenAI 必需的 models 基础字段及 Chat/Responses 结构保持。已公开的健康扩展契约被删除，按 SemVer 占用 1.0.0，控制台同步升级；依赖旧健康扩展的自建客户端需调整。0.30.2 本地未发布修复并入此版本。

## 影响模块

账号验证持久化与 Liquibase、InferenceReadinessProbe、AccountProbeService、LifecycleScheduler、模型目录/控制器/路由/运行时并发保护、相关配置/指标、Web 类型/目录/账号验证界面、API 契约、统一版本与回归。

## Self proxy 出口偏好

用户要求各厂商请求尽量经 self proxy 四节点。已核对 Self-hosted Oracle 为 NODE_LIST/4 节点；当前七家启用厂商的 INFERENCE、LIFECYCLE、REGISTRATION 统一绑定该池，保留已有节点源和 Qwen 禁用状态。修复 bindProvider 的 ON CONFLICT 没有更新 traffic_scopes 的缺漏，防止控制台换绑后仍保留仅注册范围。验证使用只读节点健康检查和路由配置证据，避免额外生成探活。

## 验收和验证

- 同一账号并发首次验证只有一条生成；重复请求、周期保活、凭据更新和重启不新增生成。成功、失败、取消/中断、历史迁入和高级模型拒绝均覆盖。
- 新账号未验证不能被一次验证逻辑标记为 READY；缓存的失败不能在每次保活反复惩罚当前账号，缓存成功不能在重复管理查询时擅自启用账号。
- 已发现且启用的模型不因探活记录、历史成功率、探活时效或模型熔断而被预先拦截；实际错误通过 OpenAI 错误契约返回。并发容量及租约失败仍明确返回。
- models 目录不扫描 usage_events 或 model_probe_results；保留 capability/参数映射、权限和 token 约束。前后端、SDK 夹具、迁移/版本/构建门禁通过。
- 真实运行验证仅使用必要的合成请求和只读检查，避免重复消耗额度；不创建/重置真实厂商账号，不恢复 Qwen，不发布 Cloudflare Worker。

## 部署、迁移与回滚

新账号在默认生命周期流程下先进入 PENDING/disabled，保留需要先重新认证的 pending-auth 顺序及 MiniMax 先签到规则；明确 `scheduleLifecycle:false` 的导入保持原可选语义。首次验证的配置 timeout 改为 account-verification-timeout，生成总时长上限 120s；保留 providers.config.probe_model 作为基础选型。新表 RUNNING 在进程中断后仍消耗一次预算，不能自动重试。

新增的每账号验证表和历史证据迁移为向后兼容，不删除现有数据；旧 0.30.1 进程忽略新表。新旧候选使用隔离缓存 key，提升已验证的不可变制品。回滚使用已验收 0.30.1 四镜像并保留新增表；回滚会恢复旧版周期探活策略，需按用户额度要求评估。

## 桥接兼容与本地验证（2026-10-13）

用户补充允许静默兼容 WEB 与 OpenAI 的差异。WebParameterAdaptation 生成独立的厂商请求视图，保留已有原生映射；常用可选生成控制没有 WEB 字段时省略，已有原生输出预算按已知上限/剩余上下文收敛。MiMo 的小输出预算不再被参数门禁拒绝。该策略覆盖普通调用、已选账号和随机路由；原始请求、历史、系统提示、工具和权限保持完整，错误类型及真实输入超限校验保留。API 契约同步记录 `best_effort_ignore/enforced:false`，不声称缺失的 WEB 控制有精确原生语义。

工具 JSON 共用批次解码器，拒绝未知工具/重复 ID 整个批次；MiMo 保留两次相同的实际调用并校验禁并行策略，限制待解析缓冲为1Mi字符。LongCat 忽略终态后帧，上游截断在 Chat 中返回 length/content_filter，在 Responses 中保持 incomplete；不将截断伪装为工具成功完成。
