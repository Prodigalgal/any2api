# Arena 生产恢复

## 目标与范围

- 用户明确授权继续实施恢复，以生产 Arena 的真实正文与完成事件为验收目标。当前生产 1.5.16 健康，但 Arena 推理未恢复。
- 先在隔离 Job 中对照历史可用的 0.30.0 与当前不可变镜像：同账号、原 Sophia 固定出口、同模型/字面量输入、各最多一次真实生成；不连接旧应用到生产数据库、不回写诊断凭据、不改账号验证预算。
- 如旧版仍被官方拒绝，验证 Arena 独立浏览器 profile 的持久化生命周期；使用服务器自己建立的独立 profile，按账号隔离、限制单写者、受现有浏览器/代理预算约束。当前官方交互验证按用户最新自主识别授权和有限预算执行。
- 隔离验证通过后，再将有证据支持的最小修复接入现有 Arena Runtime，构建新的正式三段式候选并按既有流程发布；不改变下游 OpenAI 契约。

## 非目标与安全边界

- 用户 2026-10-19 21:07 明确授权“自行注册、自行识别、自行测试”，随后要求使用系统自身完整流程。沿用系统注册、邮箱、内部视觉 AI、账号保存与一次初检能力自主推进，采用有限请求与失败停止条件；此前两组各 3 次调用仅为历史结果，不再作为当前执行阻断。computer-use 技能的逐次确认规则限于 Windows UI，不能扩展到 Linux/Camoufox 服务器流程。不移植 Google 验证状态、不复用 Token、不轮换账号出口。
- 用户追加要求按本机环境对齐容器：以当前 Edge 的实际元数据为基线，在隔离环境验证语言/时区/尺寸/显示比例及浏览器配置；区分浏览器报告值与宿主硬件，不能将 Linux/ARM64 宣称为真实 Windows/x64 或实体 NVIDIA GPU。未取得真实输出前不批量修改生产账号。
- DeepSeek/Qwen 继续停用，其他五家正常桥接保持；不新增周期生成探活。
- 不新增公开管理 API。运维交互仅通过本机绑定的私有隧道；持久 profile 作为敏感会话资料，最小权限、单账号单目录、不得提交 Git 或输出内容。

## 影响文件与实现顺序

### 2026-10-19 追加：Arena 统一 Camoufox

- **目标**：按用户最新要求，Arena 注册、重认证、保活和推理统一使用 Camoufox，旧账号保存的 `backend=patchright` 不再改变 Arena 引擎；其他厂商保持现有选择规则。
- **范围**：`providers/official_browser.py` 的局部引擎选择扩展点、`providers/arena.py`、`providers/arena_browser.py`、相关回归和统一版本文件。已有 1.5.17 制品保留，新代码候选占用 1.5.18（修复既有引擎和配置选择，不新增 API/数据库契约）。
- **指纹规则**：使用 Camoufox 原生生成/恢复的同一配置，保留 Windows、字体、Canvas、WebGL、语言、时区、地理位置及 WebRTC 一致性；启用原生鼠标轨迹模拟，不以外层固定 locale/viewport 覆盖 Camoufox。已有账号按保存的配置与代理 affinity 复用，不按请求重新随机。
- **交互一致性**：保留浏览器原生鼠标路径，移除重复的 DOM `dispatchEvent(MouseEvent)` 预热；合成事件不是可信输入，未取得官方分数时不声称其改善验证。
- **候选递进**：1.5.18 已通过 CI 并保留不可变制品。隔离验收发现新生成配置会携带默认扩展，而保存配置会移除扩展路径；同指纹、同窗口的零生成对照中，原冷启动按钮点击超时，仅移除扩展配置后点击成功。新候选占用 1.5.19，在 Arena 注册/重认证/推理统一排除 Camoufox 默认扩展，保留原生 humanize 和所有已有设备字段；其他厂商默认行为不变。重新构建后再验收，不覆盖 1.5.18。
- **点击边界进一步修正**：1.5.19 的 CI 成功，但完整模板夹具仍有 performing click 阶段超时；排除扩展及额外序列化 POC 均不足以消除。普通模板退出/发送按钮的原生键盘 Enter 激活 POC 已通过 13/13 项，含关闭恢复，0 厂家请求。1.5.20 仅将这两个普通按钮固定为原生键盘激活，不添加鼠标失败后的重复提交，不切换引擎、不关闭 humanize、不处理验证码；重新构建验收。
- **验证**：先以三个独立账号、各自原代理、各最多一条原生“你好”做 Camoufox 对照；认证身份不匹配则停止，不把历史成功标志当作当前输出。测试覆盖旧 backend 覆盖、无配置/恢复配置、参数不变性、会话复用与失败回收，再构建新的不可变候选。
- **验收与非目标**：真实正文、完成事件和复用才算 Arena 恢复；没有 Google assessment score 时不声称提高分数。不开启新的验证码自动操作，不恢复周期探活/DeepSeek/Qwen，不修改四节点绑定。

- 先使用忽略的 `backend/build/` 诊断脚本及独立 Job，保留元数据证据和资源清理记录。
- 用户截图补充的输入修复作为独立确定缺陷处理：截图对应 `/code/direct`，生产实际配置为 `/text/direct?model_a=max`，不将 Code 模板阻塞误记为生产 403 的根因。准备请求时若出现 `Exit template` 则退出，定位可见的 `textarea[name="message"]` 并排除 aria-hidden 测量框；填入原文后验证读回值、点击明确的 Send message，校验捕获的原生输入。

## 验收与回滚

### 系统自身完整注册与验证流程

- **目标/范围**：通过现有管理端注册任务验证 Arena 注册、邮件激活、凭据加密保存、一次入库初检与 OpenAI 桥接；先创建 target=1/maxAttempts=1/concurrency=1 的任务，使用原 Self Proxy 池、Camoufox、内部 AI，禁止循环批量注册。
- **缺口**：现有页面流只自动点击 v2 checkbox，没有图块识别/提交闭环。补齐 Arena 专属图块流程并复用现有 CaptchaAiPolicy/视觉 registry，不扩大其他厂商行为，不添加公开 API 或数据库字段。
- **行为边界**：只发送当前验证码区域给内部 AI；识别结果必须严格校验结构、编号、截图/选择状态；总预算最多 3 次识别，单次网络不自动重试，灰化/过期/取消即停止；图块动态替换须重新读取，禁止重复识别相同提交中画面。验证成功仅以官方结果及后续真实正文确认。
- **版本/影响**：新增图块闭环属于向后兼容能力，候选使用 1.6.0；影响 Arena challenge、视觉 registry 局部方法、相应单元与流程测试及统一版本文件，保留 1.5.21 不可变镜像和生产 1.5.16。
- **验收/测试**：成功/失败/非法结构/动态换图/灰化/超时/取消/AI 禁用/账号复用回归；全量 Automation、Backend/Web、版本契约、不可变容器零生成模拟与限次真实全链路验收。当前生产保持，完整桥接未通过则不提升。

### 1.6.1 验证失败等待修复

- **事实/目标**：1.6.0 真实系统 API 两账号均认证匹配、原配置恢复，分别触发 2/1 次内部 AI，未获得官方 v2 Token。第二账号明确记录 recognition_invalid、0 提交，但整轮仍等到约 109 秒；修复 helper 失败后未结束待定 widget 的生命周期问题。
- **范围/影响**：Arena challenge 返回类型明确区分已提交等待、widget 关闭、不可恢复失败；PageFetch 保留原 helper 兼容并增加带 request_id 的局部处理 hook；Arena 页面脚本只结束该 request 尚未完成的 challenge promise，不取消已开始生成。源码及统一版本文件占用 1.6.1，不覆盖 1.6.0。
- **重试/兼容边界**：非法 AI 结构可在确认同一题仍有效且有剩余预算时重试，整体最多 3 次、每次 1 网络请求；成功识别后已提交/灰化的同图不重复。严格 JSON、原 affinity/Camoufox、OpenAI/数据库/其他厂商契约保持；function tool POC 仅超时，没有证据时不纳入产品。
- **验收/回滚**：增加非法两次后成功、三次失败零点击、按 request_id 结束待定验证、已提交/取消不误伤、JS promise/Widget 清理回归；新不可变容器及有限真实复测。候选未验收不更新生产，回滚基线仍为 1.5.16。
- **完整流程代理缺陷**：Arena register 计算邮箱 affinity/重试偏移却未保存到凭据，后端首次推理因此可能回退账号 UUID 重新选节点；reauthenticate 又显式将偏移重置为 0。1.6.1 在两条成功路径统一保存有效 affinity/offset，并从原凭据恢复重认证偏移；后端已有两字段读取契约，不新增结构、不推测修补旧账号。测试覆盖首轮/第二邮箱成功、已有非零偏移和调用方冲突值。

### 1.5.21 发送准备延迟修复规格
