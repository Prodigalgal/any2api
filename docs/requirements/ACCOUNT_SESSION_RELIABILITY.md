# 账号会话可靠性增量重构

## 目标与范围

在原仓库保留 Java / Python 分工和现有厂商协议，本批修复会话重建、账号操作冲突和过期凭据回写。

- MiMo / MinMax 使用有界、账号独占的浏览器会话池；不同账号可并行，同账号串行。
- 空闲会话按 LRU 回收，活跃会话不被其他账号驱逐；关闭等待在途操作退出。
- 生命周期任务取得与推理共享协调域的独占账号租约，等待繁忙账号不消耗失败预算。
- 租约到期后禁止复活；凭据更新使用操作开始时版本，禁止把旧补丁重新合并到新凭据。
- 推理验证产生的最新浏览器状态纳入生命周期最终保存。

## 非目标

不迁移语言，不重写公共协议，不改变额度或厂商权限，不修改 Qwen / GLM 特有浏览器实现，不自动部署生产。
后续再迁移其专有会话模型，并实现上游候选适配器自动生成与独立发布。

## 影响模块

Automation: session_pool、official_browser、mimo_browser、minmax_browser、config。
Backend: AccountLeaseService、AccountSelectionService、LifecycleScheduler、CredentialVault。

## 验收

1. A/B/A 调用复用 A 会话；忙账号不被驱逐；同账号串行、不同账号并行。
2. 等待取消、创建失败、关闭失败后不泄漏容量；关闭后拒绝新任务。
3. 生命周期与推理互斥；过期租约不能续租；释放旧 owner 不影响新 owner。
4. 陈旧凭据补丁被拒绝，不读取新版本后重试覆盖；验证返回状态不会丢失。
5. 现有协议测试和全量 CI 通过，真实浏览器回归另需可用账号环境。

## 发布与回滚

统一候选版本 0.8.0；无数据库迁移、无公共 API 变化。默认每个接入的厂商会话池容量为 2，
通过 ANY2API_AUTOMATION_OFFICIAL_BROWSER_SESSION_POOL_SIZE 调整，单池最大 32。该值不是全服务浏览器总上限。
资源不足可设为 1；版本回滚使用上一个已验证镜像。浏览器与驱动依赖保持不变。
