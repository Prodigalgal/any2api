# Arena 容器运行环境修复（1.5.14～1.5.15）

## 目标与已知事实

- 修复 Automation 应用发布与浏览器依赖基础镜像脱节，确保实际依赖符合当前锁文件，并在构建时验证非 root 浏览器可以启动。
- 当前生产 1.5.13 的 Patchright 为 1.61.2 / Chromium 149；应用 Dockerfile 长期固定继承旧基础镜像，CI 没有将新基础镜像传给应用构建。Camoufox 0.5.4 / 浏览器 152 可启动；中文字体缺失，未发现动态库缺失、共享内存不足或 OOM。
- 同一生产账号 10 月 19 日 03:49 仍有 459 字符正文，03:54 首次转为 v2 拒绝，早于 1.5.11～1.5.13。14:41 本机 Edge 原生生成成功；14:45 Chromium、14:55 Camoufox 在服务器原生提交均被官方 403 拒绝。不能将构建缺陷直接认定为验证码故障的唯一原因。

## 范围与影响文件

- `automation/Dockerfile.browser-runtime`：从当前锁文件导出不含应用版本的生产依赖清单，构建依赖基础镜像；补齐中文字体，执行离线、非 root 的 Chromium/Camoufox 启动检查。
- 四个 Automation 应用 Dockerfile、构建校验脚本：显式传入基础镜像，在安装应用前比较锁文件导出的生产依赖，拒绝不匹配基础镜像。
- `.github/workflows/build-and-deploy.yml`、`.github/workflows/browser-runtime.yml`：基础镜像按本次不可变制品构建并以 digest 传给应用，保留只构建基础镜像入口；先构建候选，不自动发布未验收候选。
- Patchright 及锁文件、全部统一版本字段与相关测试。Camoufox 保持现有版本，不把尝试切换浏览器引擎作为生产修复。

## 非目标与兼容

- 不更改 OpenAI/数据库/权限契约、账号状态、初次验证预算、原 Self Proxy 四节点绑定；DeepSeek/Qwen 保持停用。不新增生成探活。
- 不自动完成验证码、不复用 Token、不复制 Google 验证状态，不新增指纹伪装或代理轮换。

## 追加的集群深度模拟范围

- 用户授权三个隔离容器：Chromium 有窗口、Chromium 无窗口、Camoufox 有窗口。每容器 1 个浏览器预算，CPU limit 600m、内存 limit 2Gi、shm 512Mi，非 root、无 Service/生产 selector、无服务账号 Token，完成后删除。
- 使用本地 HTTP 夹具和合成验证字段，所有浏览器请求限定 loopback；每组 12 场景覆盖 UTF-8 分块、尾帧、连续复用、同账号并发、403/429、交互验证失败、超时、取消、超限帧及失败后恢复。该模拟不证明真实厂家生成可用。
- 记录真实容器/浏览器环境，区分宿主硬件、浏览器默认报告及 Camoufox 生成值；不将伪造桌面身份作为修复。基线有窗口 Chromium 的 WebGL 不可用，EGL/GLES 系统库缺失；补齐标准运行库并在候选中记录实际 WebGL 结果。

## 1.5.15 镜像层修复

- 1.5.14 已构建并进入隔离集群测试，业务版本占用不再复用。初次镜像拉取暴露压缩镜像约 3710MiB，其中两个 1720MiB 大层来自安装依赖后递归修改所有权。
- 改为先建立 UID 10001 和可写目录，再由运行用户安装依赖/浏览器；系统库安装仍使用 root，运行与检查仍为非 root。删除递归 chown，避免整批浏览器文件重复进入镜像层。
- 全组件递增为 1.5.15，重新构建不可变制品；验收新增镜像层大小对比、相同三组离线模拟及实际运行用户/权限检查，其他契约和回滚点保持。

## 验收与回滚

- 依赖版本或锁文件不一致时构建失败；应用版本变化不改变依赖导出；CI 消费本次基础镜像 digest；构建中 Chromium/Camoufox 在非 root 环境离线生成页面并正确关闭。
- 相关回归、完整 Automation 质量、Backend/Web 构建、1.5.14 源码/JAR 版本契约通过；独立候选镜像完成实际运行环境验收后再决定提升生产，镜像不得覆盖。
- Arena 真实生成必须单独取得正文与完成帧才能记为恢复；如仍被官方验证拒绝，停止同条件重复请求并保留故障边界。
- 应用可回滚至 1.5.13 的原不可变镜像组合；保留现有资源配额、代理绑定和历史状态对账，无数据库迁移。
