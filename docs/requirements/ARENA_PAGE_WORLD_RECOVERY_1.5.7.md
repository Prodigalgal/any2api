# Arena 运行环境与页面脚本上下文修复（1.5.7）

## 目标

在 1.5.5 已部署的超时与清理边界上继续恢复 Arena。用户补充本机通过集群 HY2 访问正常，要求优先排查环境；使用现有会话、账号和同一出口做对照，不新增人工验证管理 API。

## 已验证事实

- 本机 Edge 的 Max “你好”有完整有效回答。出口 IPv6 属于 `hy2-sophia` 节点；其 IPv4 为原 Self Proxy 四节点之一的 `168.138.40.214`。
- 服务器隔离 Chromium headful 恢复这份 Arena 状态，使用同一 IPv6、同一账号，生成 200、无 v2；随后在网页对话历史中确认了完整回答。服务端 Linux 浏览器具备可行恢复路径。
- 另一份服务器历史成功账号的 Chromium headful 原生提交也为 200、无 v2；仍需独立核对最终正文，不扩展为所有账号已恢复。
- 同会话、同节点执行原 1.5.5 桥接的 headless 对照，返回 `recaptcha_v3_unavailable` 且未向上游发起生成。安装的 Patchright 1.61.2 源码确认 `page.evaluate` 的 `isolated_context` 默认 True；该上下文看不到主页面的 `grecaptcha`、官方模块导出或 fetch 包装。
- 单独切到主页面上下文后，已可取得官方 SDK/交互函数及 binding，但一次桥接仍遇 403/v2；切换上下文是必要修复，当前尚不足以证明生成恢复。继续区分 headless、原生提交上下文与浏览器引擎差异。
- Camoufox 的 `geoip=True` 在探得 IPv4 后会设置 `network.dns.disableIPv6=True`。一次对照因此从 IPv4 出站，已在生成前中止，不能把该次与原生 IPv6 的差异直接归因于引擎。

## 范围与关键取舍

1. 先以最多必要的单变量、最小提示对照验证修复。准备过程拦截提交时，上游生成次数为 0；真实提交逐次计数，保持 Token 仅在本次请求内使用。
2. 页面拥有的 SDK、模块导出、fetch 和取消 controller 在主页面上下文执行；仅对支持此参数的 Patchright 使用 `isolated_context=False`，Camoufox/Playwright 调用保持兼容，不通过异常重试两次执行脚本。
3. 若证据要求使用原生提交上下文，复用官方 UI/导出产生本次 Token 与 `cx`；保持规范请求正文、附件上传、原有 SSE 解码、取消与资源释放，禁止复用旧 Token、伪造验证成功或批量生成探测。
4. 只有在桥接验证通过后才恢复已验证账号的浏览器状态与原 Self Proxy 出口；保留现有账号身份、用户数据与回滚备份，不盲目批量转换所有会话。
   用户随后要求环境修复后验证 IPv6 池；优先逐一验证当前固定 IPv6 节点，若通过则保留该池，不必迁移出口。
5. 无下游 OpenAI API/数据库/权限契约变化，DeepSeek/Qwen 停用与定时生成探活移除保持。1.5.6 隔离候选首请求有完整输出，连续请求发现 UI 草稿状态未重置，未发布且不复用版本号；修正候选使用 1.5.7，1.5.5 制品冻结。
