# 1.5.2 浏览器与代理资源归属修复及 Arena IPv6 接入

## 目标与授权

2026-10-18，用户要求查找并使用 `168.138.40.52` 的现有 IPv6 代理，同时修复进程清理器误杀、代理与浏览器会话生命周期错配；随后要求优化代理复用，并授权按需改造 IPv6 服务。沿此前授权继续实现、测试与发布。时间统一 UTC+8。

## 范围与保留边界

- 修复清理器按进程存活 600 秒直接杀死受管浏览器的问题，保留真正孤儿/失控进程清理与请求超时保护。
- 让受管浏览器保留其 VLESS 本地代理隧道；请求结束释放流量并发租约，浏览器关闭释放隧道引用。复用同一上游节点时保留本地端口，出口或凭据变化时重建会话。
- 将隧道独立为有界池，默认每个进程最多 16 条、空闲 300 秒回收、容量满时淘汰最早空闲节点；不淘汰活跃引用，等待超过 10 秒返回明确错误。进程退出重新建代，旧引用释放不能误删新代；关闭时回收进程。
- 已验证现有 `168.138.40.52:10800` 为每连接随机 IPv6，Arena 页面仍返回 Cloudflare 403。保留此服务，新增 `10801` 固定出口入口，按认证节点持久绑定 IPv6，增加认证、限流、超时与 systemd 生命周期管理；以独立 Arena 代理池验证接入，其他厂家保持原绑定。
- 不新增代理协议或厂家能力；公开 OpenAI 契约不变，无数据库迁移，统一补丁版本 1.5.2。
- 不修改 RCM，不恢复 DeepSeek/Qwen，不增加定时生成探活，不输出或提交代理认证信息，不更改现有 10800 服务或全局网络路由。

## 设计与影响模块

- `browser_budget.py` 维护浏览器租约的受管 driver 进程身份；生命周期与各 Runtime 在启动后登记，在资源释放后解除登记。
- `process_reaper.py` 使用进程真实开始时间和父子关系保护受管进程树，检查 PID 身份后清理孤儿/无归属过期进程；磁盘扫描与退出等待继续放在线程中。
- `lifecycle/proxy.py`、`proxy_tunnels.py`：分离物理隧道所有权与每次请求的节点并发 reservation，支持有界空闲复用、创建失败、重复释放、进程退出、旧引用晚释放和并发获取。配置前缀为 `ANY2API_AUTOMATION_`，新增 `DYNAMIC_PROXY_TUNNEL_POOL_SIZE`、`DYNAMIC_PROXY_TUNNEL_IDLE_SECONDS`、`DYNAMIC_PROXY_TUNNEL_ACQUIRE_TIMEOUT_SECONDS`。
- `deploy/ipv6-proxy/`：独立固定出口服务，认证 HTTP CONNECT/HTTP 转发，仅允许公网 IPv6 目标的 80/443 端口；每节点固定源 IPv6，凭据以 systemd credential 文件加载，日志不记录认证值。补齐浏览器 HTTP 代理认证字段映射。
- `official_browser.py`、其他持久会话 Runtime 在会话中持有/释放隧道引用；保留现有容量、账号互斥、空闲淘汰和关闭顺序。
- 用现有管理 API 创建加密保存的 Arena IPv6 代理池；先保存原绑定，核对实际节点/作用域，再变更并 GET/SQL 验证。代理凭据仅存服务器管理 private 目录与后端加密存储。

## 执行与验收

1. 只读核对远端现有代理、认证与 IPv6 路由；通过现有代理读取出口地址和 Arena 页面，不新增厂家生成请求。
2. 补失败、并发、取消与资源回收回归：活跃进程超过 600 秒仍受保护、真正孤儿仍清理、PID 复用不误杀、连续请求端口稳定、API 无持有者及时关闭、浏览器关闭释放隧道、节点 reservation 不被空闲浏览器占用。
3. 运行 Automation 全量测试/Ruff、Backend 回归与 JAR 构建、Web lint/build、统一版本校验。
4. 提交推送，等待 CI 不可变镜像、GitOps、Argo 和 Pod/运行版本验收；绑定 IPv6 候选，核对实际出口及自然业务结果。
5. 记录真实连通、普通推理、验证码阻断和发布健康，不能将页面 200/目录或 Pod Ready 当作 Arena 恢复依据。

## 回滚

- 代码回滚到 1.5.1 原不可变镜像组合，保持 DeepSeek/Qwen 零副本。
- Arena 代理绑定恢复发布前的 Self-hosted Oracle 四节点及三类流量作用域；新增 IPv6 池可停用保留，便于审计。
- 现有 IPv6 服务不重启、不改全局路由；若代理不可用，先恢复原 Arena 绑定并明确记录失败原因。
