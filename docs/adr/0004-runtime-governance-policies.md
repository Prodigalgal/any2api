# ADR 0004：运行时治理策略与管理控制面

## 状态

Accepted，2026-08-11。

## 决策

### 模型 token 限制

厂商发现的模型能力继续保存在 `models.capabilities`，作为不可变的本次发现事实。管理员上限使用三个 nullable 列单独保存；`NULL` 表示继承发现值。有效值由目录缓存统一合成：有覆盖值时使用覆盖值，否则使用发现值。

覆盖值是安全上限，不是伪造厂商能力，因此已知发现值存在时禁止设置得更大。三类有效值还必须满足输入和输出上限均不大于上下文上限。

统一 `ModelRequestLimitGuard` 在具体路由解析后、账号租约前校验：

- 输出限制读取三个 OpenAI 兼容别名中的唯一已声明值；
- 输入限制使用请求 JSON 的 UTF-8 字节数除以 3 向上取整的偏保守估算；
- 上下文限制校验估算输入与显式输出预算之和。

不在各 provider mapper 中重复实现限制，也不静默截断用户值。

### 账号探测

新增 `/api/admin/v1/account-probes`，请求显式携带 `accountId` 和 `modelId`。服务校验模型归属后继续复用账号租约、失败处置、凭据 patch 和操作事件链路。旧 `/accounts/{id}/probe` 保留并选择默认模型。

探测结果返回经过长度限制的真实文本和耗时；不把输出写入账号元数据，避免持久化潜在敏感内容。独立端点允许入口网关只为探测配置长超时。

### 厂商保活策略

保活策略属于敏感运行设置，沿用 `system_settings` 的加密存储。每个厂商策略包含间隔、确定性 jitter 窗口和远端自动化参数。保留字段（凭据、元数据、代理、邮箱和亲和键）不能由参数覆盖。

调度器总是消费间隔和 jitter；自定义参数只注入远端 automation payload，本地 Java lifecycle handler 继续使用强类型接口。

### 前端边界

MUI theme、App Shell、页面数据面和状态语义集中维护。账号列表负责查询和选择，详情与探测各自是独立工作弹窗。模型策略页只编辑治理契约，不复制推理业务规则。

## 取舍

- 采用显式数据库列而非自由 JSON，换取约束、查询和迁移可读性。
- 采用统一估算器而非厂商 tokenizer，换取低延迟和跨模型一致性；精确 token 仍以厂商最终 usage 为准。
- 保留账号详情路由而不强制迁移，避免破坏书签和外部链接。

## 回滚

- 前端可回滚到旧交互，后端新端点和 nullable 列保持兼容。
- 清空覆盖列即可恢复全部发现值；Liquibase rollback 可删除新增列与约束。
- 清除 `PROVIDER_KEEPALIVE` 设置即可恢复 6 小时默认周期和 20 分钟 jitter。
